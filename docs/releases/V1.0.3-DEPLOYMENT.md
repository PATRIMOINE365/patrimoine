# Patrimoine V1.0.3 Production Deployment

## Scope
V1.0.3 contains User Management / RBAC and Activity Log. V1.0.2 remains the immutable rollback baseline.

## Pre-deployment
1. Confirm the approved V1.0.3 commit is on `main` and the `v1.0.3` tag points to it.
2. Confirm the full automated test suite, production Vite build and `git diff --check` pass.
3. Confirm the working tree is clean.
4. Take and verify a production database backup.
5. Preserve the current production `public/build`.
6. Record the current production source commit.
7. Do not edit the production database manually.

## Production source deployment
1. Deploy the approved Git `main` commit through the existing Plesk Git workflow.
2. Verify the production source commit.
3. Preserve the production `.env`.
4. Install PHP dependencies with the existing Plesk PHP/application user:
   `composer install --no-dev --optimize-autoloader`

## Database upgrade
1. Review migrations with `php artisan migrate:status`.
2. Apply them with `php artisan migrate --force`.
3. Confirm the existing V1.0.2 user is automatically promoted to Administrator.
4. Confirm existing business and financial data remains intact.

Fresh installations create the first user as Administrator through Initial Setup.

## Frontend assets
The production VPS does not currently build Vite assets.

1. On the Mac, check out the exact approved release commit.
2. Run `npm ci`.
3. Run `npm run build`.
4. Verify `public/build/manifest.json`.
5. Package `public/build` and copy it to the VPS.
6. Back up the existing production `public/build`.
7. Verify the incoming manifest.
8. Replace production `public/build` while preserving the Plesk application owner/group.

Do not install Node.js/npm globally on production merely for this release.

## Laravel caches
Run with the correct Plesk PHP/application user:
- `php artisan optimize:clear`
- `php artisan config:cache`
- `php artisan route:cache`
- `php artisan view:cache`

## Post-deployment verification
Verify:
- HTTP and login work.
- The migrated user is Administrator.
- User Management works, including invitation, resend, role change, disable/reactivate, deletion and Administrator-initiated password reset.
- Administrator, Property Manager and Viewer permissions match the frozen V1.0.3 RBAC matrix.
- Viewer write/financial controls and unavailable navigation are hidden.
- Activity Log records meaningful human actions, excludes passive/background activity, supports filtering/detail, and exports PDF/CSV.
- Activity Log exports record their own export event.
- English/French presentation works.
- GHS/FCFA presentation remains correct.
- Representative existing reports, PDFs, emails and financial workflows remain correct.
- Representative production Parties, Buildings, Units, Leases, Invoices, Payments, tenant funds and owner accounting data remain intact.
- Application logs show no release-blocking errors.

## Rollback
If a release-blocking problem occurs:
1. Stop the rollout and preserve diagnostics.
2. Restore the verified pre-deployment database backup when database rollback is required.
3. Restore/redeploy the preserved V1.0.2 application release.
4. Restore the backed-up V1.0.2 `public/build`.
5. Preserve the correct Plesk owner/group.
6. Rebuild Laravel caches as appropriate.
7. Verify V1.0.2 HTTP/login and representative business functionality before reopening normal use.

Do not move or rewrite the immutable `v1.0.2` tag, and do not use ad-hoc manual database edits as a rollback method.

## Release completion
Production deployment is complete only after source, migrations, frontend assets, authentication, RBAC, User Management, Activity Log, localisation/currency, representative financial workflows and existing production data have all been verified successfully.
